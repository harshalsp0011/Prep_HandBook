PySpark Watermarking

Structured Streaming Guide

What is Watermarking?

In PySpark Structured Streaming, a **Watermark** is a threshold used to manage late-arriving data. It defines how long the engine should wait for data that has an event-time timestamp earlier than the current maximum event time seen so far. It allows the system to balance accuracy with resource management by eventually "closing" old time windows.

Event Time Focus

Processes data based on when it actually happened, not when it arrived at the server.

State Cleanup

Automatically drops old aggregate state from memory to prevent OutOfMemory errors.

Grace Period

Defines a specific 'delay threshold' (e.g., 10 mins) to accept delayed logs.

The Comparison

Without Watermarking

The streaming engine keeps all windowed aggregates in memory forever, as it doesn't know if more late data will arrive. Eventually, the application crashes.

With Watermarking

The engine calculates a "moving floor" (Max Event Time - Threshold). Any data older than this floor is ignored, and its corresponding state is purged.

Common Applications

  • IoT Sensor Monitoring

    Handling sensors that go offline and upload packets in batches 15 minutes late.

  • Ad-Tech Click Tracking

    Aggregating clicks within a 1-hour window where network latency varies across global users.

  • E-commerce Flash Sales

    Real-time inventory updates allowing for small delays in payment confirmation events.

The Watermark Lifecycle

1

Max Event Time

Engine tracks the highest timestamp seen in the data so far.

2

Subtract Threshold

Watermark = Max Event Time - Delay Allowed.

3

Filter Input

New records with timestamp < Watermark are dropped immediately.

4

Purge State

Windows where End-Time < Watermark are deleted from memory.

Key Rule

The watermark is updated at the end of each micro-batch. This means the watermark used to filter data in Batch N is actually the one calculated from Batch N-1. This behavior ensures stability in streaming jobs.

watermarking_example.py 
from pyspark.sql import SparkSession
from pyspark.sql.functions import window, col

spark = SparkSession.builder.appName("WatermarkExample").getOrCreate()

# 1. Read Streaming Data
# Schema: { "timestamp": "2023-10-01 12:00:00", "device_id": "A1", "value": 10 }
df = spark.readStream.format("json").load("/path/to/data")

# 2. Apply Watermarking
# We allow data to be late by 10 minutes
watermarked_df = df.withWatermark("timestamp", "10 minutes")

# 3. Group by Window and Device
# Window duration: 5 mins, Slide: 5 mins (Tumbling)
windowed_counts = watermarked_df.groupBy(
    window(col("timestamp"), "5 minutes"),
    col("device_id")
).count()

# 4. Start the Stream
query = windowed_counts.writeStream \
    .outputMode("append") \
    .format("console") \
    .start()

query.awaitTermination()

The Logic Walkthrough

• withWatermark("timestamp", "10 minutes"): Informs Spark that events can be up to 10 minutes late relative to the max event time seen.

• Output Mode "append": Required for most watermark operations to ensure rows are only emitted once the system is sure no more data for that window will arrive.

• Cleanup: If the current watermark is 12:15, and a window covers 12:00 to 12:05, Spark will safely delete that window's data from memory because 12:05 is less than 12:15.

Common Interview Questions

Processing time is the clock time on the machine running the Spark job. Event time is the timestamp embedded within the data itself (when the record was generated). Watermarking only works with event time.
Actually, you can use Update mode, but it will output intermediate results. Append mode is the most common with watermarking because it guarantees that a row is only written once the watermark has passed the end of the window, ensuring finality.
You must call withWatermark on the specific column used for the windowing/aggregation. If you call it on multiple columns, Spark uses the minimum of the watermarks to ensure no data is dropped prematurely.

Pro Tip

"In an interview, always mention that watermarking is critical for Stateful Aggregations. Without it, your application has a memory leak by design. Mention that the watermark is computed based on the previous batch to sound like an expert!"

Checklist for Success

  • Column is Timestamp type
  • Same column used in GroupBy
  • Output mode is consistent
  • Checkpoint location is set
