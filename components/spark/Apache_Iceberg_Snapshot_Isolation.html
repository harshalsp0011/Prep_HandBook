Apache Iceberg Snapshot Isolation

Technical Guide v1.0

What is Snapshot Isolation?

Apache Iceberg is an open table format for huge analytic datasets. Its core superpower is Snapshot Isolation—a mechanism that ensures readers always see a consistent view of the table at a specific point in time, even as writers are simultaneously adding or modifying data.

Point-in-Time Consistency

Every query runs against a static "Snapshot." Readers are never blocked by writes, and writers don't block readers.

Time Travel

Because snapshots are immutable and persistent, you can "travel back in time" to query the data exactly as it was last Tuesday at 2 PM.

ACID Transactions

Table updates are atomic. A change is either fully visible as a new snapshot or not visible at all. No partial reads.

The Paradigm Shift

Legacy (Hive)

Changes are file-system based. If you delete a folder while a query is running, the query crashes. Concurrent writes lead to data corruption.

Modern (Iceberg)

Changes are metadata-based. Queries use an immutable snapshot ID. Even if the table is updated 100 times, the long-running query stays stable.

The Metadata Lifecycle

How Iceberg achieves isolation without blocking

1. Metadata File

The root. Tracks the 'Current Snapshot' ID and schema.

2. Manifest List

Specific to one snapshot. Points to multiple manifest files.

3. Manifest Files

Lists the actual data files and their statistics (min/max/counts).

Atomic Commit: To create a new snapshot, Iceberg writes new metadata files and performs an atomic swap of the table pointer in the Catalog (Hive Metastore, Nessie, Glue).

Iceberg SQL Operations
-- 1. Create a snapshot by inserting data
INSERT INTO prod.sales SELECT * FROM stage.sales;

-- 2. View current snapshots (each has a unique ID)
SELECT committed_at, snapshot_id, operation
FROM prod.sales.snapshots;
Output:
2023-10-01 10:00:00 | 459231... | append
2023-10-01 12:00:00 | 883102... | overwrite
-- 3. Time Travel Query
SELECT count(*) FROM prod.sales FOR SYSTEM_TIME AS OF '2023-10-01 11:00:00';

-- 4. Rollback to a specific snapshot if data is bad
CALL prod.system.rollback_to_snapshot('sales', 459231...);

Pro Interview Tip

"When asked about Iceberg, don't just say 'it's fast.' Emphasize that it separates the Physical Layout (files on S3/HDFS) from the Logical View (the Snapshot). This decoupling is what allows for concurrent ACID writes and zero-copy branching—features that were impossible in the old Hive world."
