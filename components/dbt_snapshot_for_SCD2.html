dbt Snapshots & SCD 2

Analytics Engineering

What are dbt Snapshots?

Snapshots are a specialized feature in dbt used to implement Slowly Changing Dimensions (SCD) Type 2. They allow you to capture the state of mutable source tables over time, ensuring historical context is never lost when upstream records are updated or deleted.

Time Machine

Unlike standard models, snapshots persist data versioning across dbt runs, acting as a historical ledger.

SCD Type 2

Automatically adds dbt_valid_from and dbt_valid_to columns to track row-level validity.

Change Data Capture

Implements CDC within the data warehouse without needing complex external tools or triggers.

The dbt Snapshot Lifecycle

1

Initial Load

First run captures everything. Rows marked as valid from 'Now' until 'Infinity' (NULL).

2

Change Detection

Subsequent runs compare source vs. snapshot using Unique Key + Strategy.

3

Invalidation

If a change is found, the existing row's dbt_valid_to is updated to the current time.

4

Insertion

A new row with updated values is inserted. History is now "Stacked".

1

Initial Load

Full capture of current state.

2

Detect

Check for updates using Timestamp or Check columns.

3

Invalidate & Insert

"Retire" the old row and start the new one.

Core Strategies

Timestamp Strategy Recommended

Uses an updated_at column. dbt only snapshots if source.updated_at > snapshot.updated_at.

Check Strategy

Compares specific column values. Useful when source systems don't provide reliable update timestamps.

Technical Implementation

1. File Structure

Snapshots live in the snapshots/ directory of your dbt project.

2. SQL Snapshot Block 
{% snapshot orders_snapshot %}

{{
    config(
      target_schema='snapshots',
      unique_key='id',
      strategy='timestamp',
      updated_at='updated_at',
      invalidate_hard_deletes=True,
    )
}}

select * from {{ source('main', 'orders') }}

{% endsnapshot %}

Config Parameters

  • target_schema: The DB schema where history is stored.
  • unique_key: Primary key of source row.
  • invalidate_hard_deletes: Captures if a row is deleted in source.

Auto-Generated Columns

  • dbt_scd_id: Unique hash for this row version.
  • dbt_valid_from: Start of this version.
  • dbt_valid_to: End of this version (NULL = current).

Interview Flashcards

SCD Type 1 overwrites existing records, losing history (only current state exists). SCD Type 2 (which dbt snapshots implement) tracks history by creating new rows for changes, using validity timestamps to differentiate versions.

Pro Tip: Snapshot Source, not Models

Always point snapshots at your raw sources. If you snapshot a transformed model and your transformation logic changes, it may trigger false "updates" in your history table, corrupting the audit trail.
