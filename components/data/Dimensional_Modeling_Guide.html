What is Dimensional Modeling?

A design technique for data warehouses aimed at making data easily accessible to business users and improving query performance.

Performance

Optimized for reading through denormalization, reducing complex JOIN operations that slow down traditional databases.

Clarity

Structures data in a way that aligns with business processes, making it intuitive for non-technical analysts to query.

Extensibility

Easy to add new data elements without changing existing reports, making the model highly adaptable to change.

Why Dimensional Modeling?

Moving from Operational (ER) to Analytical (Dimensional) structures.

Before: ER Modeling (3NF)

  • Normalized for write-efficiency (OLTP).
  • 20+ tables required for a simple sales report.
  • Extremely difficult for business users to understand.

After: Dimensional Modeling

  • Denormalized for read-efficiency (OLAP).
  • A central Fact table surrounded by 4-5 Dimensions.
  • Simple, fast, and visual-friendly.

Real-World Applications

Retail Analytics

Tracking daily sales by store, product, and promotion using a Star Schema.

Healthcare Reporting

Analyzing patient visits, treatment costs, and outcomes across various departments.

The 4-Step Design Process

Kimball's Lifecycle Methodology

1

Select the Business Process

Identify exactly what event we are tracking. (e.g., "Customer places an order").

2

Declare the Grain

Define what a single row represents in the fact table. (e.g., "One line item on a receipt").

3

Identify Dimensions

Who, what, where, when, why? (e.g., Customer, Product, Date, Store).

4

Identify Facts

The numerical measures. (e.g., Quantity, Sales Amount, Discount Amount).

Interview Flashcards

Master the common questions for Data Engineer / Analyst roles.

In a Star Schema, dimensions are denormalized (one level). In a Snowflake Schema, dimensions are normalized (split into sub-tables). Star schema is preferred for reporting because it requires fewer JOINs.
Techniques to handle data changes over time.
  • Type 0: Never change.
  • Type 1: Overwrite (no history).
  • Type 2: Add a new row (full history). Most common.
A single dimension table that stores multiple small, unrelated attributes (like flags, indicators, or status codes) to keep the fact table from becoming cluttered with dozens of foreign keys.

Architect Pro Tip
