Spark Performance Optimizations

Practical tactics to reduce shuffle, I/O, and skew

Partitioning Bucketing Dynamic Pruning Broadcast Join Data Skew Caching

Partitioning

The Use Case

Global app analytics where queries target a specific region.

Key Benefit

Reduces I/O by skipping entire folders.

When to use

Low-cardinality columns: date, region, category.

PySpark
df.write.partitionBy("country").parquet("s3://bucket/data")

# Spark reads ONLY the USA folder
df = spark.read.parquet("s3://bucket/data").filter("country = 'USA'")

Bucketing

The Use Case

Repeated joins on the same key across large tables.

Key Benefit

Avoids shuffle by co-locating join keys.

When to use

High-cardinality keys: user_id, product_id.

PySpark
df.write.bucketBy(64, "user_id").sortBy("city").saveAsTable("bucketed_data")

# If both tables are bucketed on user_id with same # of buckets,
# Spark can skip the shuffle stage.

Dynamic Partition Pruning

The Use Case

Join a massive fact table with a filtered dimension table.

Key Benefit

Skips partitions at runtime based on join keys.

When to use

Spark 3.0+ with broadcast hash joins.

PySpark
fact_sales = spark.table("large_fact_partitioned_by_date")
dim_date = spark.table("dim_date").filter("month = 'Jan'")

# Spark injects the filter into the scan of fact_sales
result = fact_sales.join(dim_date, "date_id")

Broadcast Join

The Use Case

Join a huge fact table with a tiny reference table.

Key Benefit

Avoids all-to-all shuffles by broadcasting small data.

When to use

Small table below the broadcast threshold (default 10MB).

PySpark
from pyspark.sql.functions import broadcast

# Force a broadcast join if needed
result = huge_df.join(broadcast(small_df), "id")

Data Skew

The Use Case

Hot keys overload a single worker and slow the job.

Key Benefit

Salting spreads the hot key across workers.

When to use

Power-law distributions or extreme key imbalance.

PySpark
from pyspark.sql.functions import concat, lit, rand

# Add salt to the large table join key
df_skewed = df.withColumn(
  "join_key",
  concat(col("id"), lit("_"), (rand() * 10).cast("int"))
)

Caching

The Use Case

Reuse expensive transformations across multiple actions.

Key Benefit

Avoids recompute; subsequent actions read from cache.

When to use

When the dataset fits memory and is reused.

PySpark
# .cache() is a shortcut for .persist(MEMORY_AND_DISK)
df = df.transform(complex_logic).cache()

df.count() # 1st action: reads from S3, stores in RAM
df.show()  # 2nd action: reads directly from RAM
