dbt Quick Prep

Data Build Tool • Analytics Engineering

The Definition

dbt (data build tool) is an open-source framework that handles the "T" in ELT (Extract, Load, Transform). It allows anyone who knows SQL to engineer data like a software engineer.

The "T" in ELT

dbt doesn't move data. It transforms data already sitting in your warehouse (Snowflake, BigQuery, etc.).

Software Best Practices

Brings Version Control (Git), Testing, Documentation, and CI/CD to the world of data analytics.

Pure SQL & Jinja

Write simple SELECT statements; dbt handles the boilerplate DDL/DML (CREATE TABLE, INSERT INTO) for you.

Common Use Cases

Cleaning Data

Standardizing date formats, cleaning nulls, and renaming cryptic column names from source systems.

Building a Metrics Layer

Schema Evolution

Seamlessly changing table structures without manual ALTER TABLE scripts.

Key Terminology

Model: A .sql file with a SELECT statement.
Materialization: How a model is built (Table, View, Incremental).
Seed: Static CSV files loaded into the warehouse.
Snapshots: Mechanism to capture Type 2 Slow Changing Dimensions.
Macro: Reusable SQL snippets (like functions).
DAG: Directed Acyclic Graph (the lineage chart).

1. The Model (orders.sql)

-- dbt handles the "CREATE TABLE" part automatically
{{ config(materialized='table') }}

WITH raw_orders AS (
  SELECT * FROM {{ source('jaffle_shop', 'orders') }}
),

final AS (
  SELECT
    id AS order_id,
    user_id,
    order_date,
    status
  FROM raw_orders
)

SELECT * FROM final

2. The Config (schema.yml)

version: 2

models:
  - name: orders
    description: "Cleaned list of shop orders"
    columns:
      - name: order_id
        tests:
          - unique
          - not_null
      - name: status
        tests:
          - accepted_values:
              values: ['placed', 'shipped', 'completed']

High-Level Questions (Flashcards)

What is the difference between a Table and a View materialization?

View: Re-run as a query every time it's accessed. No storage cost, but slow for big datasets.

Table: Physically created in the warehouse. Faster to query but needs to be "run" by dbt to update the data.

What is an Incremental Model and when should you use it?

An Incremental model only processes new or changed records since the last dbt run.

Use Case: Large fact tables (millions/billions of rows) where re-building the whole table every time is too expensive or slow.

What are the 4 Generic Tests built into dbt?
  • unique: Ensures every value in a column is unique.
  • not_null: Checks for missing values.
  • accepted_values: Validates a column only contains specific values (e.g., 'active', 'inactive').
  • relationships: Checks referential integrity (Foreign Key test).
dbt Core vs. dbt Cloud?

Core: Open-source CLI tool. You manage the environment and orchestration (e.g., with Airflow).

Cloud: SaaS version. Includes an IDE, Job Scheduler, Logging, and a Semantic Layer out of the box.
