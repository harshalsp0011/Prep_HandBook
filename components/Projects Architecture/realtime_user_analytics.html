System Architecture

High-level overview of the Kappa-Lite decoupled architecture.

Design Philosophy

The platform follows a modular, decoupled "Kappa-Lite" approach. By separating storage, compute, and consumption, we ensure that backpressure from heavy ML workloads does not impact the ingestion throughput. The system is designed for sub-minute latency and idempotent fault recovery.

Engineering "War Stories"

Reliability in streaming systems requires handling failure and time-skew gracefully. This section details our idempotency strategies and how we handle late-arriving data using Watermarking.

Idempotency & Upserts

Preventing duplicates during retries.

Logic: We use PostgreSQL ON CONFLICT. If a Spark batch fails halfway, the retry simply updates the existing rows instead of inserting new ones.

ETL/ELT Pipeline Steps

Follow the journey of a single user event from raw ingestion to a certified dataset used for ML inference.

1. Raw Ingestion

Tool: Kafka Producer

Simulates high-volume user interactions (Page View -> Cart -> Purchase). Serializes as JSON to user_events topic.

2. Schema-on-Read

Tool: Spark Consumer

Incoming JSON is strictly cast to a StructType. Malformed data is filtered immediately to protect downstream quality.

3. Windowed Aggregation

Tool: Spark Aggregator

Computes Real-time metrics (Active Users, Revenue) using groupBy and window functions.

4. Funnel Analysis

Tool: Stateful Spark Transformation

Tracks users through conversion steps. Calculates drop-off rates dynamically.

5. Certified Dataset

Tool: PostgreSQL Sink

Clean, validated data is written to Postgres. Tables are indexed on `window_start` and `user_id`.

6. ML Inference

Tool: Scikit-Learn

Reads recent behavior, applies Random Forest model, and flags high-risk churn users back to the DB.

Stakeholder Benefits

The architecture is designed to serve three distinct technical personas, balancing infrastructure robustness with data accessibility.

Data Engineer

  • Infra-as-Code: Dockerized environment ensures parity across dev and prod.
  • Fault Tolerance: Baked in via Kafka persistence and Spark checkpoints.
  • Observability: Structured logging for consumer lag monitoring.

Analytics Engineer

  • Star Schema: Clean, aggregated tables ready for BI tools.
  • No Parsing: Data is pre-flattened and validated before storage.
  • SCD Ready: Foundation laid for historical tracking.

AI Engineer

  • Feature Store: Aggregates serve as high-fidelity features for real-time models.
  • Feedback Loops: Predictions written back to DB for model monitoring.
  • Decoupled Compute: ML workload doesn't impact ingestion speed.
